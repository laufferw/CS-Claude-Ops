# Essays

Opinionated writing on CS Ops and RevOps as disciplines. Each essay argues a position, then links to the frameworks, prompts, and playbooks in this repo that put it into practice.

| Essay | Argument |
|---|---|
| [CS Ops Is a Discipline, Not a Help Desk](cs-ops-is-a-discipline.md) | CS Ops owns the system that turns customer data into decisions, not the queue of reports. AI raises the value of writing that system down |
| [Health Scores Are for Deciding, Not Reporting](health-scores-are-for-deciding.md) | A health score earns its place only if it explains itself, admits what it doesn't know, triggers action, and gets tested against what happened |
| [Prove the Value, Then Sell It](prove-the-value-then-sell-it.md) | CS survives by proving the outcomes customers chose, from a baseline, and then selling that path as Adoption as a Service |
| [Claude Drafts, People Decide](claude-drafts-people-decide.md) | Why commitments stay with people, what AI does well in CS up to that line, and how the tools enforce it |

Essays are drafts. They state opinions, so they don't follow the inputs-outputs-failure-modes template the other docs use.
